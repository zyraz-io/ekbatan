## ADDED Requirements

### Requirement: ShardingStrategy is a generic pluggable interface
ShardingStrategy<DB_ID> MUST define three methods with no default implementations: `boolean usesShardAwareId()`, `Optional<ShardIdentifier> resolveShardIdentifierById(DB_ID id)`, `Optional<ShardIdentifier> resolveShardIdentifier(Persistable<?> persistable)`. It SHALL live on the Repository, not on Persistable. Every implementation MUST explicitly implement all three methods.

#### Scenario: Strategy declares shard-aware ID support
- **WHEN** `strategy.usesShardAwareId()` is called
- **THEN** it returns `true` if the strategy resolves shards from IDs, `false` otherwise

#### Scenario: Strategy resolves shard from DB_ID
- **WHEN** `strategy.resolveShardIdentifierById(uuid)` is called
- **THEN** it returns `Optional.of(shardId)` if resolved, `Optional.empty()` if not (old record or non-sharded)

#### Scenario: Strategy resolves shard from persistable
- **WHEN** `strategy.resolveShardIdentifier(persistable)` is called
- **THEN** it returns `Optional.of(shardId)` if resolved, `Optional.empty()` if not

#### Scenario: Optional.empty() is ambiguous without usesShardAwareId()
- **WHEN** `resolveShardIdentifierById` returns `Optional.empty()`
- **THEN** it could mean "no sharding at all" (NoShardingStrategy) OR "sharding active but old record without shard bits" — `usesShardAwareId()` disambiguates

### Requirement: ShardAwareId interface for shard-carrying value objects
ShardAwareId MUST be an interface with a single method `ShardIdentifier resolveShardIdentifier()` (no parameters). Value objects that carry shard info SHALL implement it.

#### Scenario: ShardAwareId resolves from itself
- **WHEN** `shardAwareId.resolveShardIdentifier()` is called on a value object
- **THEN** it returns the ShardIdentifier encoded in that value

### Requirement: NoShardingStrategy returns empty for all resolution methods
NoShardingStrategy MUST return `false` for `usesShardAwareId()` and `Optional.empty()` for both resolve methods. It MUST be the default when no strategy is specified.

#### Scenario: NoShardingStrategy is not shard-aware
- **WHEN** `NoShardingStrategy.instance().usesShardAwareId()` is called
- **THEN** `false` is returned

#### Scenario: NoShardingStrategy resolves to empty by ID
- **WHEN** `NoShardingStrategy.instance().resolveShardIdentifierById(anyId)` is called
- **THEN** `Optional.empty()` is returned

#### Scenario: NoShardingStrategy resolves to empty by persistable
- **WHEN** `NoShardingStrategy.instance().resolveShardIdentifier(anyPersistable)` is called
- **THEN** `Optional.empty()` is returned

### Requirement: EmbeddedBitsShardingStrategy uses ShardedUUID for resolution
EmbeddedBitsShardingStrategy MUST implement `ShardingStrategy<UUID>`, return `true` for `usesShardAwareId()`, and delegate to `ShardedUUID` for shard extraction from UUID v7 bits. The bit layout is fixed: 4-bit group + 8-bit member.

#### Scenario: EmbeddedBitsShardingStrategy is shard-aware
- **WHEN** `EmbeddedBitsShardingStrategy.INSTANCE.usesShardAwareId()` is called
- **THEN** `true` is returned

#### Scenario: Round-trip resolution by ID
- **WHEN** a UUID is generated via `ShardedUUID.generate(ShardIdentifier.of(2, 5))`
- **THEN** `resolveShardIdentifierById(uuid)` returns `Optional.of(ShardIdentifier.of(2, 5))`

#### Scenario: Resolution of old non-sharded UUID (pre-migration)
- **WHEN** `resolveShardIdentifierById` is called with a pre-sharding UUID v4 (random, not generated by ShardedUUID)
- **THEN** it MUST return `Optional.empty()` — the UUID version is checked, and only v7 UUIDs are resolved. Old records fall back to default shard.

#### Scenario: Fixed bit allocation
- **WHEN** `EmbeddedBitsShardingStrategy` is used
- **THEN** 4 bits are used for group (max 16 groups) and 8 bits for member (max 256 members per group)

#### Scenario: Generated UUIDs are valid UUID v7
- **WHEN** a UUID is generated by ShardedUUID
- **THEN** the version bits are 0111 (v7) and the variant bits are 10 (RFC standard)

### Requirement: ShardedUUID is a value object implementing ShardAwareId
ShardedUUID MUST wrap a UUID, implement ShardAwareId, and provide `generate(ShardIdentifier)` and `from(UUID)` factory methods. It SHALL NOT be a singleton or utility class — each instance wraps a different UUID.

#### Scenario: Generate new ShardedUUID
- **WHEN** `ShardedUUID.generate(ShardIdentifier.of(0, 1))` is called
- **THEN** a new ShardedUUID wrapping a UUID v7 with shard (0, 1) encoded is returned

#### Scenario: Wrap existing UUID
- **WHEN** `ShardedUUID.from(existingUuid)` is called
- **THEN** a ShardedUUID wrapping that UUID is returned

#### Scenario: Extract shard from value
- **WHEN** `shardedUuid.resolveShardIdentifier()` is called
- **THEN** the ShardIdentifier encoded in the UUID bits is returned

#### Scenario: Access underlying UUID
- **WHEN** `shardedUuid.value()` is called
- **THEN** the underlying UUID is returned

### Requirement: ShardedId<T> is independent from Id<T>
ShardedId<T> MUST be a final class that wraps ShardedUUID and implements ShardAwareId. It SHALL NOT extend Id<T>. Sharded models declare `ShardedId<Wallet>` as their ID type, non-sharded models keep `Id<Wallet>`.

#### Scenario: Create ShardedId
- **WHEN** `ShardedId.of(Wallet.class, shardedUuid)` is called
- **THEN** a ShardedId wrapping that ShardedUUID is returned

#### Scenario: Generate ShardedId
- **WHEN** `ShardedId.generate(Wallet.class, ShardIdentifier.of(0, 1))` is called
- **THEN** a ShardedId with a newly generated ShardedUUID for shard (0, 1) is returned

#### Scenario: Resolve shard from ShardedId
- **WHEN** `shardedId.resolveShardIdentifier()` is called
- **THEN** the ShardIdentifier from the underlying ShardedUUID is returned

#### Scenario: Sharded model declaration
- **WHEN** a sharded model is declared
- **THEN** it uses `Model<Wallet, ShardedId<Wallet>, WalletState>` as its type parameters

### Requirement: ShardingStrategy is open for extension
The framework MUST allow clients to implement custom ShardingStrategy implementations with their own DB_ID types and shard-aware ID types.

#### Scenario: Custom strategy with Long IDs
- **WHEN** a client implements `ShardingStrategy<Long>` with hash-based routing
- **THEN** the framework uses it for shard resolution in repositories

#### Scenario: Custom strategy with custom shard-aware ID
- **WHEN** a client creates their own `ShardAwareId` implementation (e.g., `ShardedString`)
- **THEN** the framework works with it via the ShardAwareId interface
